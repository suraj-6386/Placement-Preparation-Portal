1. AIVEN CONNECTION DETAILS & SERVICE URI
================================================================================
In Aiven MySQL, connection details are provided on the Overview tab of your service.

CRITICAL:
 Database Name: Use the database name shown by the current Aiven service.
 Do not assume it is `defaultdb` or `skillprep_db`.
  Aiven service. If your service is recreated, the hostname changes. Never guess or
  reconstruct hostnames. Always copy the active Service URI directly from Aiven Console.

Example Aiven Connection Format:
  DB_HOST     = <your-current-aiven-hostname>.aivencloud.com
  DB_PORT     = <your-aiven-port>
  DB_USER     = <username-from-current-aiven-service>
  DB_NAME     = <database-name-from-current-aiven-service>
  DB_PASSWORD = <your-aiven-password>


2. ENVIRONMENT VARIABLES FOR RENDER (Production)
================================================================================
In your Render Web Service dashboard -> Environment:

Required Environment Variables:
DATABASE_URL=mysql+pymysql://avnadmin:<PASSWORD>@<CURRENT_AIVEN_HOST>:<PORT>/<DATABASE_NAME_FROM_AIVEN>?ssl-mode=REQUIRED&charset=utf8mb4

APP_ENV=production

Optional / Recommended on Render:
BASE_URL=https://<YOUR-RENDER-SERVICE-NAME>.onrender.com
GOOGLE_CLIENT_ID=<your-google-client-id>
GOOGLE_CLIENT_SECRET=<your-google-client-secret>
SECRET_KEY=<strong-random-secret-key>

NOTE ON DRIVER SCHEME:
  automatically converts `mysql://` to `mysql+pymysql://` if needed.
  percent-encoded (e.g. '@' -> '%40').


3. WHY DID STARTUP FAIL WITH "[Errno -2] Name or service not known"?
================================================================================
The error `socket.gaierror: [Errno -2] Name or service not known` indicates a DNS
resolution failure:
1. The hostname configured in Render was non-existent or no longer registered in DNS.
   (e.g., the previous test service was terminated, deleted, or recreated).
2. Fix: Open your Aiven Console, select your active MySQL service, copy the active
   Service URI, and update `DATABASE_URL` in the Render dashboard.


4. WHY WAS THERE A DATABASE NAME MISMATCH?
================================================================================
The database name is service-specific. Verify it in the current Aiven Connection
Information panel or with `SELECT DATABASE()` and `SHOW DATABASES`. Using an old
or guessed name causes MySQL error 1049 (unknown database). The application models
and table initialization run inside the database named in the current DATABASE_URL.


5. ENVIRONMENT VARIABLE PRECEDENCE & PRODUCTION ISOLATION
================================================================================
  When `APP_ENV=production` or running on Render (`RENDER=true`), the application:
  * REQUIRES `DATABASE_URL` to be explicitly provided.
  * FORBIDS connections to `127.0.0.1`, `localhost`, or local MySQL credentials.
  * Will NOT fall back to local database settings.
  * Loads environment variables with `override=False` so Render dashboard settings
    always take priority over any local `.env` files.

  * Kept completely independent.
  * Uses local MySQL credentials (`127.0.0.1:3306/skillprep_db`).
  * If `DATABASE_URL` is omitted, builds local connection URL automatically.

7. SAFE STARTUP DIAGNOSTICS
================================================================================
On startup, the FastAPI lifespan outputs sanitized database diagnostics:
  [DB DIAGNOSTICS] Database Host: <host>
  [DB DIAGNOSTICS] Database Port: <port>
  [DB DIAGNOSTICS] Database Name: <database>
  [DB DIAGNOSTICS] SSL/TLS Enabled: True

Passphrases, tokens, usernames, and complete connection URLs are NEVER logged.


8. STEP-BY-STEP RENDER DEPLOYMENT CHECKLIST
================================================================================
[ ] Step 1: In Aiven Console:
    - Confirm MySQL service status is green ("Running").
    - Note the Service URI and database name exactly as shown by Aiven.
[ ] Step 2: In Render Dashboard:
    - Navigate to your Web Service -> "Environment".
    - Set `APP_ENV` = `production`.
    - Set `DATABASE_URL` to the exact current Aiven URI, using its current database name and `ssl-mode=REQUIRED`.
      (Replace <PASSWORD>, <HOST>, and <PORT> with active values from Step 1).
    - Ensure `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` are NOT set in Render.
    - Set `BASE_URL` to your Render URL: `https://<your-app>.onrender.com`.
[ ] Step 3: Deploy:
    - Trigger Manual Deploy -> "Deploy latest commit".
[ ] Step 4: Check Logs:
    - Look for:
      [DB DIAGNOSTICS] Database Host: <aiven-host>
      [DB DIAGNOSTICS] Database Port: <port>
      [DB DIAGNOSTICS] Database Name: <current-aiven-database>
      [DB DIAGNOSTICS] SSL/TLS Enabled: True
      [OK] Connected to database: <aiven-host>:<port>/<current-aiven-database>
      [OK] Database tables verified/initialized
